# GESTIÓN DE RIESGOS DEL PROYECTO

## 1. Matriz de Evaluación de Riesgos

| ID | Descripción del Riesgo | Probabilidad | Impacto | Estrategia de Mitigación |
|---|---|---|---|---|
| R-01 | Cambios en los requerimientos durante el desarrollo | Alta | Alto | Organizar los cambios mediante incrementos y versiones funcionales. |
| R-02 | Errores en el cálculo de las rachas de hábitos | Media | Alto | Realizar pruebas con diferentes registros de cumplimiento y periodos. |
| R-03 | Problemas en la visualización de gráficos | Media | Medio | Realizar pruebas con diferentes cantidades de datos y validar los resultados mostrados. |
| R-04 | Retraso en el desarrollo de nuevas funcionalidades | Media | Medio | Dividir las funcionalidades en tareas pequeñas y dar seguimiento mediante el tablero Kanban. |
| R-05 | Problemas en la estructura de la base de datos al agregar nuevas funciones | Media | Alto | Diseñar la estructura considerando futuras categorías, etiquetas, puntos, niveles y medallas. |
| R-06 | Dificultades de uso de la interfaz | Media | Medio | Realizar pruebas de uso y ajustar la interfaz a partir de los problemas encontrados. |

## 2. Estrategia de Gestión

Los riesgos serán revisados durante las diferentes etapas del desarrollo. Cuando se detecte un riesgo, se analizará su impacto sobre las funcionalidades existentes y se establecerá una estrategia de mitigación.

El enfoque incremental permitirá incorporar cambios de manera progresiva, reduciendo el impacto de modificaciones sobre el sistema existente.
